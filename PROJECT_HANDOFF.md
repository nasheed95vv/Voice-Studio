# PROJECT_HANDOFF.md

Этот документ описывает **фактическое текущее состояние кода проекта** на момент его
составления. Он основан на прямом анализе исходников, а не на пересказе истории чата.
Если что-то из старой переписки противоречит этому документу — актуален этот документ,
потому что он написан по реальному коду.

Сборка (`./gradlew build`) на момент составления документа **ни разу не завершалась
полностью успешно** — последние присланные логи содержали ошибки компиляции, которые были
исправлены точечно, но повторный запуск сборки после этих исправлений мне не присылали.
Это означает: весь код ниже описан как "написан и должен работать по логике", но
**не подтверждён финальной успешной сборкой**. Это самое важное, что должен знать новый чат.

## 1. ИНФОРМАЦИЯ О ПРОЕКТЕ

- **Название приложения:** Voice Studio
- **Назначение:** офлайн-диктофон и аудиоредактор для Android — запись голоса, редактирование
  (обрезка/разделение/fade/удаление тишины), DSP-эффекты, экспорт в M4A, организация записей
  (папки/теги/заметки), микширование с фоновой музыкой. Полностью без доступа в интернет.
- **Платформа:** Android (нативное приложение)
- **Язык программирования:** Kotlin
- **UI-фреймворк:** Jetpack Compose + Material3, навигация — Jetpack Navigation Compose
- **package / applicationId:** `com.studioislam.voicestudio` (debug-сборка: суффикс `.debug`)
- **minSdk:** 26 (Android 8.0)
- **targetSdk:** 34
- **compileSdk:** 34
- **versionCode / versionName:** 1 / "1.0.0"
- **Java/Kotlin target:** JVM 17
- **Compose compiler extension:** 1.5.14, Compose BOM `2024.06.00`

### Основные зависимости (из `app/build.gradle.kts`)
- `androidx.compose.material3:material3` + `androidx.compose.material:material-icons-extended`
- `androidx.navigation:navigation-compose:2.7.7`
- `androidx.room:room-runtime/room-ktx:2.6.1` (+ ksp `room-compiler`)
- `androidx.datastore:datastore-preferences:1.1.1`

  `INTERNET`-разрешение отсутствует в манифесте.

## 2. ПОЛНАЯ СТРУКТУРА ПРОЕКТА

58 файлов Kotlin в `app/src/main/java/com/studioislam/voicestudio/`:

### Корень пакета
- `MainActivity.kt` → точка входа, `NavHost` (Record/Library/Settings), система `Overlay`
  (полноэкранные модальные экраны поверх NavHost: Editor/Effects/BatchEffects/Mixer/Merge/
  Trash/About/Document), нижняя навигация, тема приложения, `LocalSnackbarHostState`
  (CompositionLocal для единого механизма Snackbar-уведомлений по всему приложению).
- `VoiceStudioApp.kt` → `Application`-класс.

### `audio/` — весь DSP и работа с файлами, чистый Kotlin без сторонних аудио-библиотек
- `WavFileWriter.kt` → потоковая запись WAV во время захвата с микрофона.
- `WavEditor.kt` → `readInfo`, `trim`, `split`, `deleteSelection`, `applyFade`, `removeSilence`,
  `autoTrim`, `merge` — все операции редактора работают через этот файл.
- `WaveformExtractor.kt` → извлечение массива пиков для статичной waveform (редактор/библиотека).
- `AudioEffectsEngine.kt` → `EffectSettings` (единая структура всех параметров эффектов),
  `NormalizeMode`, `VoiceChangerPreset` (7 пресетов: None/Helium/Deep/Chipmunk/Robot/Female/Male),
  применяет весь DSP-стек к файлу.
- `AacExporter.kt` → кодирование WAV→M4A/AAC через `MediaCodec`+`MediaMuxer`, `ExportQuality`
  (Voice 64kbps / Standard 128kbps / High 256kbps).
- `MediaStoreExporter.kt` → сохранение готового .m4a в публичную "Музыку" (`MediaStore` на API 29+,
  прямая запись + `WRITE_EXTERNAL_STORAGE` на API 26-28).
- `SpeechDetector.kt` → анализ записи на речь/тишину для вкладки "Речь" в редакторе (только
  информационный анализ, файл не изменяется).
- `Mixer.kt` → сведение голоса с фоновой музыкой (ресемплинг, зацикливание, раздельная громкость).
- `AudioDecoder.kt` → декодирование произвольного аудиоформата (mp3/m4a/ogg и т.п.) в WAV через
  `MediaExtractor`+`MediaCodec`, используется `Mixer`'ом для импорта фоновой музыки через SAF.
- `EditHistoryManager.kt` → Undo/Redo через файловые снапшоты (глубина 5) + человекочитаемая
  метка операции (`.label.txt` рядом со снапшотом) для экрана "История изменений".

### `audio/dsp/` — низкоуровневые DSP-примитивы (13 файлов)
`ClickPopRemover.kt`, `DeEsser.kt`, `DynamicsProcessor.kt` (компрессор+лимитер), `Echo.kt`,
`Equalizer.kt` (+ `EqPresets`: Flat/Speech/Bass/Treble), `FFT.kt` (Cooley-Tukey radix-2),
`FormantShifter.kt`, `HumRemover.kt` (50/60 Гц), `NoiseReducer.kt` (спектральное вычитание),
`Normalizer.kt` (Peak/Loudness), `Reverb.kt`, `RingModulator.kt` ("робот"-эффект), `TimeStretcher.kt`
(скорость/тон).

### `data/` — Room + DataStore
- `AppDatabase.kt` → версия схемы **5**, 4 таблицы, 4 миграции (см. раздел 9).
- `Recording.kt`, `Folder.kt`, `Tag.kt`, `RecordingTagCrossRef.kt` → Entity-классы.
- `RecordingDao.kt`, `FolderDao.kt`, `TagDao.kt` → DAO.
- `SettingsStore.kt` → DataStore Preferences, все настройки приложения (см. раздел 13).

### `recording/` — фоновая запись
- `RecordingService.kt` → `Foreground Service`, весь жизненный цикл записи, MediaStyle-уведомление,
  Audio Focus, автопауза при звонке, автосохранение заголовка WAV на случай сбоя.
- `RecordingState.kt` → глобальный singleton-объект с `StateFlow`: `isRecording`, `isPaused`,
  `autoPauseReason`, `levelDb`, используется и сервисом, и UI (ViewModel подписывается на него).

### `security/`
- `AppLockManager.kt` → PIN хранится как SHA-256 хэш в `EncryptedSharedPreferences`
  (AES256-GCM через Android Keystore).
- `LockScreen.kt` → экран ввода PIN + биометрия (`BiometricPrompt`).

### `ui/` — экраны (Compose)
- `RecordingViewModel.kt` → **единственная** ViewModel всего приложения, вся бизнес-логика
  (см. раздел 3 — полный список функций).
- `RecordScreen.kt` → экран "Запись" (главный экран, redesign "Premium Dark Audio Studio").
- `LibraryScreen.kt` → библиотека записей: поиск/сортировка/фильтры, папки, множественный выбор,
  контекстное Bottom Sheet-меню записи, диалоги (переименование/теги/заметка/перемещение
  в папку/история изменений/удаление с подтверждением), empty state.
- `EditorScreen.kt` → редактор с вкладками Trim/Split/Fade/Delete/Silence/AutoTrim/Speech.
- `effects/EffectsScreen.kt`, `effects/BatchEffectsScreen.kt` → применение DSP-эффектов
  (одиночное и пакетное — идентичный набор параметров и визуальный стиль).
- `MixerScreen.kt` → наложение фоновой музыки.
- `MergeScreen.kt` → объединение нескольких записей в одну.
- `TrashScreen.kt` → корзина (восстановление / удаление навсегда).
- `settings/SettingsScreen.kt` → все настройки приложения.
- `AboutScreen.kt`, `DocumentViewerScreen.kt` → "О приложении" + просмотр
  Privacy Policy/Terms/Third-Party Notices (тексты — ассеты в `assets/`, **требует проверки**,
  см. раздел 6).
- `ExportDialog.kt`, `BatchExportDialog.kt` → диалоги экспорта в M4A (одиночный/пакетный).
- `WaveformView.kt` → `LiveWaveform` (живая waveform во время записи, 5 стилей),
  `EqCurveCanvas` (график кривой эквалайзера), `dbToZone`/`VolumeZone`.

### Эффекты и обработка
Единый набор для одиночного (`EffectsScreen.kt`) и пакетного (`BatchEffectsScreen.kt`) режимов,
визуально идентичные (карточки-группы `GroupCard`):
- Шумоподавление (Noise Reduction, регулируемая интенсивность)
- Очистка: Hum Removal (50/60 Гц), Click/Pop Removal, De-Esser
- Нормализация громкости: Peak / Loudness (LUFS, пресеты Broadcast/Podcast/Streaming —
  раскладка чипов исправлена на `FlowRow` в последней сессии, см. раздел 6)
- 5-полосный эквалайзер с пресетами (Flat/Speech/Bass/Treble) + **график кривой EQ**
  (`EqCurveCanvas` — новое в последней сессии)
- Динамика: компрессор, лимитер
- Пространство: Echo, Reverb
- Скорость/тон/форманты
- Voice Changer — 7 готовых пресетов
- Пакетный режим: прогресс-бар "Обработка N из M", всегда Save as new (Replace не поддерживается
  для батча — сознательное решение, риск непредсказуемости без покадрового подтверждения)

Все ✅ ГОТОВО по коду, ❓ ТРЕБУЕТ ПРОВЕРКИ — качество звука самих DSP-алгоритмов никогда не
проверялось на слух (нет возможности запустить приложение в этой среде).

## 8. ЛОГИКА ПРИЛОЖЕНИЯ

- **Запуск:** `MainActivity.onCreate()` → запрос разрешений (RECORD_AUDIO, POST_NOTIFICATIONS
  на API 33+) → чтение настроек темы из DataStore → если App Lock включён, экран разблокировки
  первым; иначе сразу `VoiceStudioNavHost`.
- **Навигация:** Jetpack Navigation Compose с 3 постоянными вкладками (Record/Library/Settings)
  + система `Overlay` (sealed class) для полноэкранных модальных экранов поверх NavHost —
  Editor/Effects/BatchEffects/Mixer/Merge/Trash/About/Document. Оверлей и NavHost взаимоисключающи
  (либо показан NavHost, либо один из оверлеев).
- **Создание записи:** `RecordingService` (Foreground Service) пишет WAV напрямую на диск во
  временный файл (`tmp_recording/active_recording.wav`) во время захвата; по Stop файл
  финализируется и остаётся временным до подтверждения сохранения; `confirmSave()` копирует его
  в постоянное хранилище (`recordings/`) под выбранным именем и создаёт запись в Room.
- **Редактирование:** все операции (Trim/Fade/Delete/Remove Silence/Auto Trim/эффекты/Mixer)
  работают по паттерну "Save as new" (создаёт новый файл) или "Replace" (перезаписывает
  оригинал, но сначала делает файловый снапшот для Undo через `EditHistoryManager`).
- **Удаление:** запись → корзина (`deletedAtMs` timestamp, не физическое удаление) → либо
  восстановление, либо безвозвратное удаление (файл с диска стирается). Автоочистка корзины по
  сроку хранения при каждом запуске приложения.
- **Сохранение настроек:** DataStore Preferences, реактивно через `Flow`, применяется мгновенно
  (без кнопки "Сохранить" — каждое изменение сразу пишется).
- **Уведомления:** MediaStyle-уведомление во время активной записи с кнопками Pause/Resume/Stop,
  через `NotificationCompat.Builder` + `MediaSessionCompat`.
- **Фоновые процессы:** `RecordingService` — единственный длительный фоновый процесс,
  `foregroundServiceType="microphone"`.
- **Обработка ошибок:** частично — есть обработка ошибки экспорта (permission denied), но
  унифицированного "Error state" паттерна (раздел 49 исходного ТЗ редизайна — "нет доступа к
  микрофону" и т.п.) по всему приложению НЕТ, реализовано не везде.
- **Восстановление после перезапуска:** `CrashRecoveryChecker` ищет осиротевший временный файл
  записи при следующем запуске и предлагает восстановить/отбросить (❓ ТРЕБУЕТ ПРОВЕРКИ — файл,
  реализующий этот объект, не выверен построчно в рамках этого анализа, но используется в
  `RecordingViewModel.kt` и, судя по всему, находится в `recording/`).
- **Взаимодействие между экранами:** через единственную `RecordingViewModel` (AndroidViewModel,
  общий на весь NavHost — создаётся один раз через `viewModel()` в `VoiceStudioNavHost`) и
  колбэки (`onEdit`, `onEffects`, `onMixer` и т.д.), меняющие состояние `overlay` в
  `MainActivity`.

## 9. ДАННЫЕ И ХРАНЕНИЕ

- **База данных:** Room, файл `voicestudio.db`, версия схемы **5**, 4 таблицы:
  `recordings`, `folders`, `tags`, `recording_tag_cross_ref`. 4 миграции (1→2 папки, 2→3 корзина,
  3→4 теги, 4→5 заметки) — все миграции присутствуют в коде, ручные (`ALTER TABLE`/`CREATE TABLE`),
  не auto-migration.
- **Настройки:** DataStore Preferences (`voicestudio_settings`), полный список ключей — раздел 13.
- **Файлы записей:** WAV-файлы на диске приложения (`filesDir/recordings/`), временный файл
  захвата — `filesDir/tmp_recording/active_recording.wav`.
- **История правок (снапшоты):** отдельная папка на диске (управляется `EditHistoryManager`, не
  в БД) — по одному WAV-файлу на снапшот + текстовый файл-метка (`.label.txt`), глубина 5.
- **Настройки блокировки (PIN):** `EncryptedSharedPreferences` (AES256-GCM через Android
  Keystore) — SHA-256 хэш PIN, не сам PIN.
- **Что удаляется:** запись в корзине по истечении срока хранения (настройка) — и файл с диска,
  и строка в БД, и история правок, и связи с тегами.
- **Что сохраняется между запусками:** все записи, папки, теги, заметки, настройки, PIN-хэш.
- **Экспортированные .m4a файлы:** либо в публичную "Музыку" через MediaStore, либо через
  системный Share Sheet — не хранятся и не отслеживаются приложением после экспорта.
- Никакого сетевого хранилища, синхронизации или облака — не придумано, в коде нет.

## 11. АУДИО

- **Источник звука:** микрофон устройства через `AudioRecord`, источник настраиваемый
  (`MediaRecorder.AudioSource`: `VOICE_RECOGNITION` (дефолт), `MIC`, `VOICE_COMMUNICATION`,
  `CAMCORDER`).
- **Форматы:** запись всегда в WAV PCM16 (внутренний рабочий формат); экспорт — AAC в
  контейнере M4A. Импорт фоновой музыки для Mixer — любой формат, поддерживаемый системным
  `MediaCodec` (mp3/m4a/ogg и т.д.), декодируется в WAV.
- **Частоты дискретизации:** 8000/16000/22050/44100/48000 Гц, настраивается.
- **Каналы:** моно/стерео, настраивается.
- **Хранение выбранного звука (фоновая музыка для Mixer):** не сохраняется отдельно — SAF-выбор
  каждый раз заново, файл декодируется во временный WAV и используется однократно для сведения.
- **Работа при заблокированном экране:** Foreground Service продолжает писать; управление через
  MediaStyle-уведомление и медиа-кнопки должно работать на экране блокировки (❓ ТРЕБУЕТ
  ПРОВЕРКИ — не подтверждено на реальном устройстве).
- **Известные проблемы:** качество самих DSP-алгоритмов не проверялось на слух (см. раздел 6).

## 12. УВЕДОМЛЕНИЯ

- **Единственный тип:** уведомление активной записи (Foreground Service), канал
  `recording_channel` (`IMPORTANCE_LOW`), MediaStyle с кнопками Pause/Resume/Stop.
- **Появляется:** при старте записи, обновляется при паузе/автопаузе/возобновлении, исчезает
  при остановке (`stopForeground(STOP_FOREGROUND_REMOVE)`).
- **Разрешение:** `POST_NOTIFICATIONS` (Android 13+).
- **Каналы:** один (`recording_channel`).
- **Отключение:** через системные настройки приложения (нет отдельного тумблера в самом
  приложении, кроме общей возможности не давать разрешение).
- **После перезапуска телефона:** нет `BOOT_COMPLETED`-обработчика — уведомление не
  восстанавливается автоматически (и не должно, т.к. запись не переживает перезагрузку).
- Пункты про "изменение времени" и "удаление события" из шаблона документа неприменимы — в
  приложении нет календарных событий/напоминаний.

**Какие функции ещё не реализованы:** раздел 5-C и строки 🔴 в чеклисте раздела 17 —

**Какие баги нужно исправить:** на момент составления этого документа нет ни одного известного
ОТКРЫТОГО бага — все 9 из обратной связи пользователя исправлены по коду. Единственная
неопределённость — подтверждение через реальную сборку и повторное тестирование.

**Какие файлы наиболее важны:**
- `RecordingViewModel.kt` — вся бизнес-логика, единственная ViewModel.
- `RecordingService.kt` — жизненный цикл записи, самая чувствительная к багам зона.
- `MainActivity.kt` — навигация, Overlay-система, тема, общий Scaffold.
- `Theme.kt` — вся дизайн-система, включая динамический акцентный цвет (легко сломать заново,
  если не использовать `MaterialTheme.colorScheme.*`).
- `LibraryScreen.kt` — самый большой и функционально насыщенный экран.
- `WavEditor.kt`, `AudioEffectsEngine.kt` — весь DSP/редактирование.
- `AppDatabase.kt` — схема БД, версия 5, если потребуется добавлять персистентные маркеры —
  сюда нужна миграция 5→6.

**Важно для стиля работы с этим пользователем:** пользователь тестирует на реальном устройстве
и даёт подробную, конкретную обратную связь по пунктам — реагировать на каждый пункт отдельно,
находить настоящую причину (не косметический патч), объяснять коротко в чём была причина. Не
считать функцию готовой, если это не подтверждено. Предпочитает, чтобы разработка продолжалась
без лишних остановок и переспрашиваний, но при этом ожидает реальной, а не выдуманной точности.
